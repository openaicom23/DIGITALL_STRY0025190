За decimal поле в ServiceNow няма атрибут в речника, който сам да забрани отрицателните стойности. Ограничението се слага с валидация: client script за формата и business rule, за да важи и при API, import и background.

„Положително“ тук е по-голямо от 0. Ако 0 трябва да минава, смени проверката на < 0.

1. Client script (onChange)
Тип: onChange, полето е твоето decimal поле.

function onChange(control, oldValue, newValue, isLoading) {
    if (isLoading || newValue === '') {
        return;
    }
    if (parseFloat(newValue) <= 0) {
        g_form.showFieldMsg(control, 'Стойността трябва да е положителна.', 'error');
        g_form.clearValue(control);
    }
}
Това спира потребителя във формата. През REST, import set или background script не минава.

2. Business rule (задължително)
When: before
Insert и Update
Condition (по избор): полето не е празно
(function executeRule(current, previous) {
    var value = parseFloat(current.getValue('u_your_decimal_field'));
    if (!isNaN(value) && value <= 0) {
        gs.addErrorMessage('Стойността трябва да е положителна.');
        current.setAbortAction(true);
    }
})(current, previous);
Смени u_your_decimal_field с името на колоната.

Ако полето е catalog variable, client script-ът е Catalog Client Script (onChange), а сървърната проверка е в Catalog Client Script onSubmit плюс бизнес правило върху sc_req_item / променливата, или в flow, който създава записа. Client-only проверката пак се заобикаля.
